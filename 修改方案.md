# Spatial-DsRA v3 修改方案

## 修改概述

依据用户提供的《Spatial-DsRA v3.md》实施，并按用户补充要求同步改造 **openvla-SF 与 openpi-SF 的 PyTorch 空间对齐训练链路**。SLA、JAX 训练、机器人部署接口及动作损失定义不在此次修改范围。完整代码已写入表中所列文件。

核心严格对应方案第 3–8 节：读取多模态 Transformer **每一个 Block 的视觉 Patch 输出**，共享逐 Token LayerNorm、降维投影、低秩基 M 和升维投影；每层仅持有独立 rho，经有界 tanh 形成对角调制系数。各层独立计算与同一个冻结 VGGT 目标的余弦距离，再对层均匀平均。没有加入层门控、层特征聚合、额外动作头或其他损失。

公式为：`B_l = GELU(LN(H_l) W_down + b_down)`，`B_tilde_l = B_l + ((B_l @ M) * a_l) @ M.T`，`U_l = B_tilde_l W_up + b_up`，其中 `a_l = gamma * a_max * tanh(rho_l)`。

总损失：`L_action + alpha * L_align + beta_R * mean(a**2) + eta * ||M.T M - I||_F**2`。第三阶段完全去掉两个正则项，冻结辅助模块所有参数（包括 LN 和偏置），但绝不对输入 H_l detach 或把辅助前向包进 no_grad。

### 维度核查（最高优先级）

| 环节 | OpenVLA 常见配置 | π0 常见配置 | 对应检查 |
| --- | --- | --- | --- |
| Backbone 层数 L | 32，从实际模块读取 | 18，从实际模块读取 | 拒绝 hidden_states 数量不等于 L |
| 原始视觉 H_l | `[B,N,4096]` | `[B,N,2048]` | 每层检查 B、N、dv 全维度 |
| 降维 B_l | `[B,N,256]` | `[B,N,256]` | Linear(dv,256) |
| 共享 M | `[256,32]` | `[256,32]` | 正交初始化；rank 不大于 db |
| 每层 rho | `[32,32]` | `[18,32]` | 第一维从实际层数取得 |
| 低秩系数乘积 | `[B,N,32]` | `[B,N,32]` | 沿末维广播该层的 32 个系数 |
| 低秩残差回投 | `[B,N,256]` | `[B,N,256]` | 与 B_l 同形状相加 |
| VGGT 有效 Patch 特征 | `[B,V,P,2048]` | `[B,V,P,2048]` | 去掉 camera/register 等全局 Token |
| 最终 U_l、Y | `[B,N,2048]` | `[B,N,2048]` | 末维实际为 `2 * VGGT.embed_dim` |
| π0 有效掩码 | 不适用，当前固定分辨率 Patch 全有效 | `[B,N]` | 相机有效掩码 AND 下采样 padding 掩码 |

**2048 的依据**：两个分支的 VGGT aggregator 都将 frame/local 与 global 特征在最后一维拼接。`embed_dim=1024` 是每一路的宽度，拼接后 d_g=2048。方案第 9.1 节中的 d_g=1024 是参数量算例，不能覆盖实际代码的输出维度。实现读取实际教师配置，并在损失入口严格核对输出通道。

**视觉位置**：OpenVLA 序列是 `BOS + 图像 Patch + 可选 proprio/time + 文本/动作`。读取 `[1:1+N]`，N 由视觉 Patch 数量取得，并排除 proprio/time；原 `gain_feat_1move=True` 的偏移不再使用。通过 Block hook 保留最后一个 Block 在最终 LN 之前的输出。π0 在 Block 计算之后收集隐藏态，仅取 prefix 中前 img_len 个 Token；不监督 suffix 状态或动作，不把输入 embedding 当作第一层。

**空间重采样**：先显式双线性插值至学生每相机网格，再加位置编码，最后按 `[相机, 行, 列]` 展平。保留现有 SF 的 UV 正弦位置编码及 0.1 幅度约定。当前两个学生编码器均使用方形 Patch 网格，遇到无法匹配的网格直接报错，不隐式 reshape。π0 使用实际学生增强后的 RGB 像素逆归一化后送入教师；原对齐预处理已经关闭几何增强，现有 padding 掩码坐标仍有效。

### 三阶段与超参数

| 参数 | 本次默认值 | 来源/说明 |
| --- | ---: | --- |
| db / r / a_max | 256 / 32 / 0.5 | 方案推荐值 |
| alpha | 0.5 | 方案推荐值；π0 对齐配置原本已有此值 |
| LoRA rank | 32 | 方案推荐；全部语言 Transformer 的 Attention Q/V |
| T1 | 20,000 | 方案推荐；以优化器更新次数计 |
| Tr | 40,000 | 对应 20K–60K 释放周期 |
| Stage III 起点 | 100,000 | **用户授权按经验暂定，方案未给定** |
| beta_R / eta | 1e-4 / 1e-4 | **用户授权按经验暂定，非已验证最优值** |
| M/rho 学习率倍率 | 0.1 | 用户授权暂定；落实方案“较低学习率”建议 |
| 总步数 | 150,000 | OpenVLA 默认、π0 现有对齐示例配置采用方案初始预算 |

0–20K：rho=0，M/rho 冻结；共享投影、LN、LoRA、动作模块训练。20K–100K：解冻 M/rho，gamma 从 0 线性升至 1，60K 后保持 1。100K–150K：冻结整个辅助模块，只通过固定映射向主干传播空间梯度。视觉编码器遵循基座设置；π0 保留其原视觉编码器训练范围，语言模型改为 Q/V LoRA，action expert 及动作投影保持全量训练。

参数先全部注册到 DDP 与 optimizer，再按阶段切换 requires_grad；因此第二阶段解冻后不会漏掉参数。关闭 π0 的 static_graph，因为各阶段的参数使用情况会改变。M/rho 的较低学习率覆盖预热与衰减；两个分支每层损失、调制范数和 LoRA 梯度范数均加入日志。

## 使用与交付说明

### 完整代码文件

- `openvla-SF/prismatic/models/spatial_dsra.py`：全层投影、低秩调制、损失、阶段管理、缓存与诊断。
- `openvla-SF/vla-scripts/finetune_align.py`：OpenVLA 全层提取、Q/V LoRA、VGGT、训练/验证/恢复的完整集成。
- `openpi-SF/src/openpi/models_pytorch/spatial_dsra.py`：同一辅助实现，保持两个独立子项目可单独使用；测试保证两份文件一致。
- `openpi-SF/src/openpi/models_pytorch/spatial_lora.py`：π0 Q/V LoRA 与原始架构部署权重导出。
- `openpi-SF/src/openpi/models_pytorch/gemma_pytorch.py`：全部 Block 输出收集。
- `openpi-SF/src/openpi/models_pytorch/pi0_align_pytorch.py`：π0 逐层空间损失与教师坐标对齐。
- `openpi-SF/scripts/train_align_pytorch.py`：三阶段训练、监控和完整保存恢复。
- `openpi-SF/src/openpi/training/config.py`：v3 参数及 150K 对齐示例。
- `tools/prepare_spatial_teacher.py`：Stage 0 离线缓存入口。
- `tests/test_spatial_dsra.py`：可独立运行的 CPU 验证。

### 训练入口

仍使用原来的 `openvla-SF/vla-scripts/finetune_align.py` 和 `openpi-SF/scripts/train_align_pytorch.py`，数据与模型路径沿用各子项目说明。新的配置名统一使用 `dsra_` 前缀；可覆盖上述暂定超参数。

OpenVLA：使用 `--use_vlm_norm True --use_vggt_pe True --gain_feat_1move False --vla_layers_align -1`（均为新默认值）；此处 -1 是兼容旧命令行字段的哨兵，**实际始终监督全部层**。与 v3 矛盾的单层、错位或取消 PE/LN 选项会显式报错。离散动作模式的 LM 输出头通过 modules_to_save 保持全量训练。π0 默认对齐示例 `pi0_align_aloha_place_block` 更新到 150K；其他非对齐配置保持原值，若拿来训练 v3，必须保证总步数覆盖 Stage III。

### Stage 0 离线缓存

先用训练相同的图像预处理得到教师输入 `[V,3,H,W]` RGB Tensor，并保存为 `.pt`。manifest 中每条记录包含 `sample_id`、有序 `camera_ids`、`images_path`。从项目根目录执行：

```bash
python tools/prepare_spatial_teacher.py --branch openvla --checkpoint /path/vggt_model.pt --manifest /path/manifest.json --output /path/teacher_cache
```

π0 将 branch 换成 openpi。训练时设置 `dsra_teacher_cache` 到同一路径。缓存保存 BF16 Patch 特征、图像/特征网格、教师权重指纹、教师层与相机顺序；index.json 记录数据集样本 ID 到缓存条目的映射。先离线缓存是方案 Stage 0 的推荐用法，但工具不自行猜测数据集目录或生成虚假的教师特征。

随机增强后，如果像素/类型/形状/相机顺序与离线输入不同，会重新计算并保存对应条目，绝不把不同坐标系的特征直接对应。默认 cache=None 时按照方案 §3.3 对增强图像在线计算冻结教师。精确像素哈希会带来 CPU 传输和磁盘开销，随机颜色增强可能使缓存命中率很低；固定预处理离线缓存时收益更明显。

### 保存、恢复与推理

OpenVLA：辅助参数另存 align_projector 文件；新增 spatial_training.pt 存优化器、调度器、已完成更新次数及未合并基座位置；LoRA 从 lora_adapter 恢复，加载未合并基座避免重复叠加。恢复仍需要保留原基座文件路径。原 SF 的 MLP 辅助权重不能当作新 DsRA 辅助权重严格加载，须从基座开始新实验。
